What We Built: Rule-Based Refusal Policy
Manipulation Detected

1

The RoBERTa classifier flags the incoming user utterance as manipulative (confidence above threshold). Normal utterances
bypass the policy entirely and receive a standard assistant response.

Scenario Classification

2

The flagged text is scanned for keywords mapped to scenario tags such as guilt_trip, pressure, flattery, threat and victimhood.
This lightweight keyword match requires no additional model call.

Template Response Issued

3

A deterministic template is selected for the matched scenario. Every template follows a fixed structure: (a) acknowledge the
user's feelings, (b) set a clear boundary, (c) offer a constructive alternative path forward.

Key design choice: no free-form generation in the refusal path. Templates guarantee the model cannot be tricked into producing unsafe output through the refusal response itself.

Summary and Takeaways
What We Achieved

Known Limitations

✓ Working detector

! Precision at 70%: 161 normal utterances are mis-flagged as
manipulation.

RoBERTa fine-tuned on 2,915 dialogues achieves 97.25%
recall, catching nearly all manipulation instances.

✓ Safe refusal path
Deterministic template policy with zero free-form generation.
The refusal itself cannot be exploited.

! Binary only: technique identity (which of 11 types) is not yet
predicted.
! Single-turn only: multi-turn manipulation patterns are not yet
captured.

✓ Fully local pipeline
No API calls, no cloud cost. Runs entirely on CPU with opensource libraries: PyTorch, HuggingFace, scikit-learn.

✓ Modular codebase
Five clean modules (data_loader, train, refusal_policy,
evaluate, demo) that can be swapped or extended
independently.
